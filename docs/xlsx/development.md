## 検証上の区別

`tests/input.rs` 内で組み立てる ZIP は入力検査用の合成データであり、
Excel が生成した正解 fixture ではない。
現時点では Excel / LibreOffice の参照 PDF は存在せず、紙面の一致は未検証。
参照資料が揃うまで、互換性や顧客向け品質を保証済みと表現しない。

`tests/support/mod.rs` は書体名・cmap・メトリクス等を持つ最小 sfnt を独自生成する。
実フォントの字形を含まず、商用フォントのコピーではない。
これによるフォントテストは選択・計測・欠落検出の制御を検証するもので、
実際の文字描画や高度な shaping の再現性を証明しない。

2026-10-20 にローカルの Excel 16.105.3 と LibreOffice の存在を確認。
`tools/excel-date-reference.applescript` を作成して検証用ブックの生成を試みたが、
保存が完了せず、GUI 確認もツールのアプリ操作権限で拒否された。
呼び出しは AppleEvent タイムアウト（-1712）で終了した。
Excel 側に検証用ブックが開いたままの可能性がある。
`tests/fixtures/excel-date/` のロックファイルは参照成果物に数えない。
このスクリプトは開発時の手動検証用で、CLI の実行時依存ではない。

`cargo clippy --all-targets -- -D warnings` を実行する。

## 字下げの計測

## OS 標準フォント探索

`--system-fonts` を指定した場合だけ、標準探索先を明示パス一覧へ追加する。
既存の件数・深さ・ファイル容量・総容量制限と、決定的なパス順での読み込みを使う。

- macOS: `/System/Library/Fonts`、`/Library/Fonts`、`$HOME/Library/Fonts`。
- Windows: `%WINDIR%/Fonts`、`%LOCALAPPDATA%/Microsoft/Windows/Fonts`。
- Linux: `/usr/share/fonts`、`/usr/local/share/fonts`、`$XDG_DATA_HOME/fonts`
  （未設定時は `$HOME/.local/share/fonts`）、`$HOME/.fonts`。

存在しない標準先は除外する。相対パスの環境設定、読み込み拒否、探索先外へのリンクは
明示的なエラーとする。Fontconfig の設定・キャッシュ、Windows レジストリ、
OS のフォントダウンロード機能には依存しない。独自のインストール先は
`--font-dir` で指定する。sandbox 側でも探索先の読み取り許可が必要。

標準先の根拠は [Apple のフォント配置](https://support.apple.com/en-ie/122869)、
[Windows Fonts フォルダ](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid)、
[Fontconfig](https://fontconfig.pages.freedesktop.org/fontconfig/fontconfig-user.html)。
全 OS の候補生成と CLI の明示指定を合成テストで検査。
Windows・Linux の実機動作および OS フォント集合全体での変換は未検証。

## フォント名の符号化

macOS の `Apple Braille Outline 6 Dot.ttf` は英語 Mac Roman の名前だけを持ち、
従来の Unicode 専用復号で `font_family_name_missing` になっていた。
英語の Mac Roman レコードと Windows encoding ID 10 の UTF-16BE 名に対応した。
Roman の言語別変種は混同せず未対応とし、ファイル名から書体名を推測しない。
UTF-16 の奇数バイト末尾や不正サロゲートを切り捨てて名前にすることも避ける。

根拠: [OpenType name 表](https://learn.microsoft.com/en-us/typography/opentype/spec/name)、
[Mac Roman 対応表](https://www.unicode.org/Public/MAPPINGS/VENDORS/APPLE/ROMAN.TXT)。
合成フォントで名前復号から書体選択まで検査し、実フォントを個別指定した
スモークも読み込みを通過した（変換自体は `rendering_not_implemented`）。
OS 全体の探索は次に `font_file_limit` で停止しており、容量制限は緩めていない。

索引確認と本体読み込みには同じファイルハンドルを使い、パスを再度開かない。
索引確認後にパスを別ファイルへ差し替えても元のフォントを読むことと、
本体読み込み時にもサイズ制限を適用することをテストした。

および [日本語対応の議論](https://listarchives.libreoffice.org/ja/users/msg00793.html)
は比較項目を選ぶ資料にとどめ、Excel の正解値の代用にしない。

## 日付時刻の十進計算

日付シリアルの整数部と小数部の分離、秒・ミリ秒への換算は、保存された
十進表記から行う。`f64` の大きな通算日を引いて小数部を得る計算を除いた。
丸め境界の前後、指数表記、日付の繰り上がり、経過時間、範囲上限をテストする。
日付だけの書式では時刻の丸めによって日付を進めない。

この変更は保存値に対する計算精度の検証であり、Excel 内部の二進数演算や
表示丸めとの一致を証明しない。境界値を Excel で保存・出力した fixture により、
採用する丸め規則を確認する必要がある。CLI の未完成状態は変わらない。

## 日付と数値の混在区分

日付を含む表示形式を最大 4 区分へ分解し、数値書式と同じ条件選択に接続した。
正数の日付、負数の括弧付き数値、ゼロの固定文字、文字列専用区分を混在できる。
日付区分の条件は保存値の丸め前に評価し、色とロケールは選ばれた日付区分に従う。
引用符、エスケープ、空白幅・埋め文字指定に使われるセミコロンは区切りにしない。

未選択の区分も解析し、未対応の書式を黙って無視しない。
条件の重複や不正な配置、5 区分以上、文字列用区分での日付描画は拒否する。
負の日付シリアルの表示と DBNum は引き続き未対応。
合成テストで区分選択と書式出力を確認済み。Excel の実出力との照合は未完了。

## 印刷範囲で使用する罫線の検出

ページ組み立て前の罫線検査を、全スタイル表から実際の印刷セルへ変更した。
行・列の書式を明示セルの書式で上書きし、空白セルにも既定書式を適用する。
未使用の罫線定義やページ外だけの罫線でページ全体を拒否しない。
検出した罫線には、シート順とセル番地を付ける。

結合範囲がページと交わる場合は、ページ外にある左上セルの書式も検査する。
結合内部の罫線は保守的に拒否する。境界の描画・競合解決・線幅の再現は未実装。
検査の作業数を制限し、列数に比例した全セル展開は行わない。
行列書式、明示セルによる上書き、ページ外セル、結合の回帰テストを追加した。

## 文字列の横方向の可視範囲

`text_overflow::Occupancy` はセル値を保持せず、占有位置と結合範囲を索引化する。
`clip` は左揃えで右側、右揃えで左側、中央揃えで両側の空セルへ可視範囲を広げる。
元セルの配置原点・内容幅は変えず、結果を `cell_text::Frame.clip` に渡す。
数値・折り返し・結合セルの範囲は広げない。空文字列は空セルと区別する。
非表示列はページ軸に存在しないため占有障害にせず、結合セル・繰り返し列と
本文の境界・ページ端で止める。処理量には索引構築と各問い合わせの上限を設ける。

6 件の合成テストで範囲、印刷倍率、境界、診断、PDF の切り取り命令と文字抽出を確認した。
これは Excel 参照 fixture との一致を確認するための配置 API であり、CLI の
既定動作にはまだ接続していない。塗り・罫線・ページ端・結合との相互作用や
文字用のセル余白を含め、Excel の実出力との照合が必要。

## 自動折り返しの計測と描画

`measure_wrapped` は Unicode の改行候補を実フォントで再計測し、収まる候補を選ぶ。
単一行に収まる文字列は一度だけ計測する。長文の再計測バイト数と候補走査、
生成行数を制限し、候補がない長い単語は任意の文字位置で分割せず拒否する。
空白を削除せず、LF の空行・末尾改行も保持する。
セル組版では、折り返し指定かつ呼び出し側が行送りを与えた場合に使う。
行送りが不明なまま複数行を描くことはない。

依存に `unicode-linebreak` 0.1.5（Apache-2.0）を追加。
[実装の公開資料](https://docs.rs/crate/unicode-linebreak/0.1.5)を確認し、
開発用 SBOM・NOTICE 生成を再実行した。実行時のネットワークや外部プロセスは不要。
英字・日本語の行分割、空白保持、上限、指定行送り、PDF 文字抽出を合成テストで検査。
Excel 固有の禁則、行末空白、長い単語の分割は未検証であり、CLI の変換成功には
接続していない。Unicode の標準規則だけで Excel と同一だとは判定しない。

## 画像キャッシュの内容識別と上限

画像キャッシュのキーを ZIP 内の部品パスから画像データへ変更した。
別の入力パッケージで同じパスを使う画像を取り違えず、内容が同じ画像は共有する。
キーは入力パッケージのバイト列を借用し、圧縮画像を再コピーしない。
Rust のライフタイムでキャッシュのキーが入力より長く残らないようにする。

キャッシュに存在する画像でも、現在の一画像・全画像・寸法の上限を再検査する。
展開サイズ計算と合計加算はオーバーフローを検査する。
異なる画像の合計超過、同じ画像の共有、入力間の同名部品、上限縮小時の拒否を
回帰テストで確認した。既存の workbook 読み込みは一冊ごとにキャッシュを生成する。

## 文字量上限の早期検査

## ページ上の罫線候補

`page_borders::edges` で、非結合セルの辺をページ上端原点のポイント座標へ移す。
セル要素のない空白にも行・列の既定書式を適用し、明示セルの書式を優先する。
ページ軸にない非表示行列は生成せず、繰り返し領域を含む軸の倍率・原点を使う。
返すのは辺、線種、解決済みの色、シート番号・セル番地であり、セル値は保持しない。

隣接セルが共有辺に異なる指定を持つ場合は、双方を別候補として保持する。
これは確定した描画命令ではなく、優先順位・線幅・交点処理を追加するための入力。
結合範囲がページに現れる場合は、外周規則を推測せず左上セルの位置付きで停止する。
走査作業と候補数には共通の上限を適用する。

行書式と明示セルの上書き、非表示列を挟む共有辺、繰り返し列、縮小倍率、色・線種、
結合の拒否、不正なページ変換、上限の境界を合成データで検査した。
既存のページ描画は罫線を引き続き拒否し、Excel との一致や CLI の変換成功は未検証。

## 複数字形クラスタの Unicode 対応

PDF 出力で一律拒否していた複数字形クラスタのうち、元の各 Unicode 文字と
整形後の各字形が同じ順番でフォントの cmap に一致するものを扱うようにした。
各字形へ元の一文字を ToUnicode で対応させ、整形後の送り幅・オフセットを保持する。
一字形の合字は、従来どおり元の文字列全体に対応させる。

字形の置換・並べ替え・個数の変化を伴う複数字形クラスタは、誤った文字を
割り当てず `pdf_multi_glyph_cluster` で停止する。これらにはクラスタ全体の
ActualText 等が必要で、抽出器側の対応も含めた実装・検証が残る。
[PDF Association の文字符号化の説明](https://pdfa.org/understanding-utf-8-in-pdf-2-0/)
も、文字の描画と Unicode 情報の対応を別途保持する必要性を説明している。

結合アキュートアクセントを含む試験フォントで、同一クラスタ・ゼロ送りの字形を
実際に生成し、PDF の全字形座標、抽出文字列、バイト列の決定性を検査した。
アクセントとセディーユの字形順が入れ替わる入力は拒否することも確認した。
試験フォントのアウトラインは空であり、実フォントの見た目や Excel との一致を
証明するテストではない。CLI の未実装停止は継続している。

## 日本語 DBNum の桁変換

`[DBNum1-3]` のうち、`[$-411]`・`[$-0411]`・`[$-ja-JP]` が明示された
非負の整数表示を追加した。`0` / `#` の数値部分だけを漢数字・大字・全角数字へ
変換し、引用文字・接頭辞・接尾辞の数字は変換しない。既存の丸め、ゼロ埋め、
区分選択、色指定を適用する。文字列セルは数字へ変換しない。

[LibreOffice 開発者の互換性検討記録](https://listarchives.libreoffice.org/ja/users/msg00794.html)
では、DBNum の `0` と `General` は異なる出力として扱われている。
この区別を実装上も保持する。参照した記録は Excel 本体で生成した当プロジェクトの
fixture の代わりにはならず、現段階の変換結果は実 Excel との照合待ちである。

ロケール不明・日本語以外、負数、小数、桁区切り、指数、百分率、会計、General、
日付の DBNum は引き続き拒否する。特に General の万・億などの単位を桁変換で
代用しない。DBNum が複数ある場合や数値パターン途中の指定も拒否する。
必須要件全体の DBNum 対応を完了したという意味ではない。

三種の桁変換、ゼロ埋めと丸め、リテラル保護、色・区分・文字列の保持、
対応外の拒否を追加し、表示形式・日付・セル文字の計 62 テストが通過した。
CLI の未実装停止および参照 PDF による照合の必要性は変わらない。

## DBNum のロケール伝達

`NumberFormat::parse_with_locale` を追加し、書式にロケール指定がない場合に
呼び出し元の明示ロケールを使用する。`cell_with_context` と日付・数値の混在区分も
この入口を使用する。ロケールを渡さない従来の `parse` は DBNum のロケールを
推測しない。OS 設定の参照は追加していない。

区分内の明示ロケールを継承値より優先する。日本語コンテキストでも `[$-409]` は
日本語の桁変換に流さず拒否し、逆に英語コンテキストの `[$-411]` は日本語として扱う。
一つの区分のロケールを隣の区分へ持ち越さない。

日付・DBNum の条件区分を両方向で選択するセル試験と、ロケール優先順位の試験を追加。
表示形式・日付・セル文字の計 64 テストと Clippy が通過した。
この変更は既存の非負整数 DBNum の範囲を接続するもので、小数や日付自体の
DBNum 変換、Excel 参照との照合は引き続き未完了。

## 混在する書字方向の検査

全ターゲットのテストを実行し、それまでの変更が通過することを確認した。
続く確認で、整形器の先頭文字体系からの方向推定だけでは、欧文で始まる行の
後続にある RTL 文字を検出できないことを合成フォントで再現した。

`FontFace::shape_run` で、字形参照・整形の前に Unicode の双方向クラスを調べる。
R・AL・AN および方向の埋め込み・上書き・分離の制御文字を検出した場合は
`text_direction` で停止する。双方向 run の配置はまだ未実装であり、この変更で
誤った一方向の描画に流れる経路を閉じた。文字の内容は診断に含めない。

既存の間接依存 `unicode-bidi 0.3.18` を直接依存に追加した。
使用 API は [bidi_class](https://docs.rs/unicode-bidi/0.3.18/unicode_bidi/fn.bidi_class.html)。
ヘブライ文字・アラビア文字・アラビア数字・補助面の Adlam を実際に cmap に持つ
試験フォントで、欧文先頭の方向推定が LTR でも拒否することを確認した。
方向制御文字の拒否と、欧文・日本語・数字の既存の混在入力も検査した。

変更後のフォント・PDF・セル文字の計 48 テストと Clippy は通過。
SBOM・NOTICE・原文資料 268 件を `target/dependency-artifacts-bidi` に生成し、
依存ライセンスの許可リストによる検査も通過した。

## 共有辺の罫線候補整理

`page_borders::coalesce` を追加した。一ページ分の候補について、線分・線種・色が
すべて同じ共有辺を一本にする。線種または色が異なる共有辺は `border_conflict`、
部分的に重なる線分は `border_partial_overlap` として位置付きで停止する。
Excel の優先順位は未検証なので、太い線や後のセルを勝手に採用しない。

端点が接するだけの隣接線分は連結しない。特に破線の位相や交点処理を変更しない
ための区別である。座標は許容差を設けず比較し、-0 と +0 だけを同じ座標として扱う。
候補数を制限し、非有限・斜め・逆向き・長さゼロの線分と不正位置を拒否する。
外部構築された不正なセル文字列を診断へコピーしない。

共有辺の一致・色違い・線種違い、部分重なり、隣接、上限・入力不正を検査し、
罫線候補・ページ組版の計 13 テストと Clippy が通過した。
これは候補整理の処理であり、線幅・交点・結合外周の描画および Excel 参照との
一致を証明しない。ページ描画での罫線拒否はまだ継続している。
