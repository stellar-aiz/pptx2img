# 分数書式の実装候補と未解決差分

この変更は Draft。組み込み書式12・13の候補実装であり、Excel と同じ表示を
確認できていない。下記の差分を解決するまでマージ可能と判定しない。

## 実装範囲

組み込み12を `# ?/?`、13を `# ??/??` へ解決する。
保存十進字句を整数部と小数部へ分け、連分数の収束分数を計算する。
次の分母が9または99を超える直前の候補を採用する。
十進桁の整数演算で除算・比較し、二進浮動小数点への変換は行わない。
整数への繰り上がり、負数区分、色、必須整数部 `0` を扱う。

分子は右詰め、分母は左詰めとし、`?` の不足桁は `Fragment::Space('0')`、
整数だけの行のスラッシュは `Fragment::Space('/')` へ渡す。
空白を固定ポイント幅へ置き換えず、実際のフォントで計測する。
PR #8 の行単位描画を使い、配置用空白で分割された文字を改行なしで抽出する。
固定分母、仮分数、三桁以上の分母、百分率等との組み合わせは未対応。

## 比較結果

Microsoft の[分数表示の説明](https://support.microsoft.com/ja-jp/excel/display-numbers-as-fractions)
で分母の桁数を指定する書式の存在を確認した。
丸めの具体的な選択はその説明だけでは確定しない。

[SheetJS SSF の公開テスト](https://github.com/SheetJS/ssf/blob/0df2ab980280401609eb6ea6b67c70d792ad73ca/test/fraction.json)
から、上記二形式の23件を比較した。21件は表示文字列と配置空白を含めて一致し、
次の2件は不一致だった。空白の比較では配置用空白を一文字の空白へ変換しており、
紙面上の幅を比較した結果ではない。

| 書式 | 値 | この実装 | 公開テストの期待値 |
| --- | --- | --- | --- |
| `# ?/?` | `0.3` | `1/3` | `2/7` |
| `# ?/?` | `2.3` | `2 1/3` | `2 2/7` |

公開テストは Excel 参照 PDF の代替ではない。値の二進表現や計算中の丸めが
収束分数の選択に影響する可能性があるが、Excel の内部規則は未確認。
差が出た値だけを特例で書き換えたり、比較結果を合格へ変更したりしない。

## 検証

Rust 全276試験、Clippy、整形・差分検査が成功。
これは現実装の算術・配置契約に対する回帰試験で、Excel 一致の証拠ではない。

- 分母の桁制限、整数への繰り上がり、符号、色、配置空白を保持。
- 二進浮動小数点では同じ値になる十進境界を区別。
- ブックの組み込み番号からセル描画、PDF 抽出、幅不足警告へ接続。
- 同じ入力から PDF のバイト一致を確認。

## マージ前に必要な証拠

同じブックに `0.3`、`2.3`、`12.3`、`1.5625`、`0.1`、`0`、負数を置き、
組み込み12・13を指定した Excel 保存 PDF と表示結果を取得する。
アプリ版・OS・ロケール・実フォント・元入力ハッシュを固定する。
その結果から十進値と二進値の扱い、分数選択、整数・ゼロの表示、空白幅を確定し、
差分と修正テストを追加する。通常 CLI の既定組版も別途必要。

## 再現用ブックの生成

Excel 参照取得用の非機密ブックを、開発用 example から生成する。
第二引数は観測環境で使用する書体名。フォント本体は同梱しない。

```sh
mkdir -p target/fraction-observation
cargo run --locked --offline --example make-fraction-probe -- \
  target/fraction-observation/input.xlsx Arial \
  > target/fraction-observation/input.json
```

出力先が存在すると停止し、入力ブックと既存の参照を上書きしない。
同じ指定から生成する XLSX のバイト列は固定する。

- A列は元の十進字句の文字列。B・D列は書式12、C・E列は書式13。
- B・C列の列幅は16、D・E列は4。広い列での分数選択と狭い列の幅不足を観測する。
- 16行にゼロ・整数・正負の小数、既知の不一致値と繰り上がり境界を配置する。
- 印刷範囲は `A1:E16`、A4縦、倍率100%、余白0.5インチ、保存行高22ポイント。
- 数式・マクロ・外部リンクを含まず、参照の期待文字列は埋め込まない。

標準出力の JSON は入力 SHA-256、列の書式と幅、各行の十進字句と binary64
ビット列を記録する。実際のフォント版・ファイルハッシュ・代用の有無は
未確認として `null`、参照 PDF は `unobserved` で初期化する。
この JSON が存在するだけでは参照取得済みにならない。

生成されたブックを Excel で開き、入力を再保存せず PDF として保存する。
Excel の版・OS・ロケール・使用フォントと代用の有無を記録し、PDF のハッシュと
開いた後の入力ハッシュを追加する。LibreOffice についても独立した記録を作る。
元入力のハッシュが変わった場合は同じ入力条件の参照とは扱わない。
自動のアプリ操作はこの生成器には含めない。

観測ブックは二回生成してバイト一致、アプリへ渡す前のライブラリ読込で
全80セル・印刷範囲・書体名・列幅・書式番号を確認した。
既存出力への再実行は終了2で拒否し、入力ハッシュが変わらないことも確認した。
追加後の Rust 全277試験、Clippy、整形・差分検査が成功。
