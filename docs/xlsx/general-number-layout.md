# General 数値の幅依存組版

## 接続範囲

`text_layout::measure_general_number` は保存済みの十進字句と実フォント、
ポイントサイズ、利用可能な幅から表示行を選ぶ。`cell_text::plan` は
組み込み番号0と、保存された `General` 書式をこの経路へ渡す。
通常 CLI の既定余白・行送りはまだ接続していない。

幅を持たない `format::cell_with_context` や `NumberFormat::parse` は、
General 数値の文字列を勝手に確定せず、従来どおり幅未解決を返す。
数式も保存済みキャッシュの型と十進字句を使い、再計算しない。
`[Red]General` や条件・DBNum と組み合わせた書式は今回の対応に含まれない。

## 根拠と実装上の判断

[ECMA-376 第1部](https://ecma-international.org/publications-and-standards/standards/ecma-376/)
§18.8.30 および
[Microsoft の numFmt 文書](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.numberingformat)
は、固定小数の表示上限を符号を除き11文字とし、利用可能幅により指数表記へ
切り替える規則を記載している。小数点と先頭のゼロも文字数に含む。
指数が -3 未満で固定小数の有効桁を失う場合には、指数表記で残せる桁数を比べる。

実装では次の候補を十進演算で生成し、実書体で計測する。

- 固定小数：小数点以下10桁から0桁まで丸め、末尾の不要なゼロを除く。
  11文字以内に収まる候補を精度の高い順に調べる。
- 指数表記：仮数1桁以上、`E`、指数符号、最低2桁の指数を使う。
  丸めで仮数が10になる場合は指数を繰り上げる。
- 負号は文字数上限から除外するが、実幅には含める。
  非ゼロをゼロ表示へ丸めて幅に収めることはしない。
- 両形式が収まらない場合は既存の `#` 埋め文字と幅不足警告を使う。
  `#` が1文字も入らない幅は、未検証の切り取りを行わず停止する。

指数表記候補にも符号を除く11文字の上限を適用する実装としている。
この指数の上限、丸めの境界、比例幅での選択順は Excel 参照との照合が必要で、
公開仕様の記述だけで Excel の全挙動と一致すると判断していない。
CLI の既定成功経路へ投入する前の検証事項として残す。

## 検証と残作業

Rust 全251試験、Clippy、整形・差分検査が成功。
共通の幅不足処理を整理した後、表示・セル配置・文字計測の試験を再実行した。

- 桁上がり、11桁の境界、小数末尾ゼロ、負数、ゼロ、大小の指数。
- 比例幅による固定小数と指数の選択、印刷倍率、幅不足と警告の原子性。
- 組み込みとカスタム General、PDF 文字抽出、同じ入力の PDF バイト一致。
- 不正な字句・幅、保存字句の欠落、文字量制限を回避しないこと。

試験書体はこのリポジトリの合成書体で、実帳票の字形や紙面を示すものではない。
実フォントと Excel 全ページ参照の照合、General の複合書式、通常 CLI の
既定組版、初版全体の完成判定は未完了。
